# Migrating Host Metadata from Termius

[繁體中文](TERMIUS_MIGRATION.md) | **English**

MyTerm can import `myterm-termius-host-export-v1` JSON generated by the repository's conversion tool, preserving host names, addresses, ports, usernames, nested groups, and recognizable platform information. Before import, it previews groups, hosts, duplicate connections, and invalid entries. Existing data is not changed until you confirm.

## Understand the data boundaries

- The MyTerm app does not directly open or parse the Termius Vault database.
- `scripts/TermiusExport/export_decrypted_metadata.js` is an optional advanced conversion tool, not an official one-click Termius exporter. It accepts only compatible host/group metadata and converts fields locally using the installed Termius runtime.
- The repository deliberately provides no tool to read or extract the Termius Vault database. If you have only the Termius app and no compatible metadata input, you cannot run this script directly to complete migration.
- The tool does not read or output passwords, private keys, private-key passphrases, tokens, or other login credentials. For hosts using private keys, it preserves only a marker that a key was referenced; configure SSH Agent, SSH config, or a local private key again after import.
- Termius internal modules are not a public API controlled by MyTerm. Their paths or format may change with Termius updates. Without compatible input, use plaintext exports officially provided by Termius as a reference for manual migration, or create hosts manually in MyTerm. MyTerm does not directly import generic CSV or raw Termius Vault files.

Even without passwords, exports can reveal real host names, IPs, usernames, groups, and internal infrastructure. Treat them as private configuration, and do not commit them to GitHub, issues, or public messages.

## Conversion requirements

- An Apple Silicon Mac.
- Termius installed at `/Applications/Termius.app`, with the current macOS user able to open their own Termius data normally.
- Compatible metadata JSON with top-level `groups` and `hosts` arrays, without password or private-key fields.
- Only process data you own or are authorized to administer, and retain an original backup first.

## Generate an importable file

This example writes to the repository's `Exports/Termius/` directory. All of `Exports/` is excluded from Git and is suitable for private local migration output:

```sh
ELECTRON_RUN_AS_NODE=1 /Applications/Termius.app/Contents/MacOS/Termius \
  scripts/TermiusExport/export_decrypted_metadata.js \
  /path/to/metadata-input.json \
  Exports/Termius
```

On success, it produces:

- `termius-hosts.json`: structured data MyTerm can import, created with `0600` permissions.
- `termius-hosts.csv`: for manual inspection only; MyTerm does not import CSV directly. Permissions are also `0600`.

The JSON `summary` reports counts for groups, hosts, missing usernames, private-key references, and duplicate connections based on that input. These are not fixed MyTerm limits.

## Import into MyTerm

1. Choose Data → Import Host Data, or Settings → Import & Export, in MyTerm's Chinese interface.
2. Select the generated `termius-hosts.json`.
3. Review the groups, hosts, duplicates, and invalid entries. To validate a small sample first, switch to custom selection and choose only a few hosts.
4. Confirm to apply the data. MyTerm first backs up the current host inventory locally.
5. Reconfigure passwords, private keys, or other authentication settings that were not migrated, then test a few connections first.

Duplicates are identified by host address + port + username. They are skipped by default, with an option to keep both; MyTerm does not directly overwrite existing hosts.

## Clean up private output

After migration and once you have confirmed your backup strategy, you can delete JSON/CSV files in `Exports/` that are no longer needed. First confirm they are not still required for import or recovery. Repository build and release workflows do not depend on these files.
